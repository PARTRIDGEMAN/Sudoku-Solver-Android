# Build setup

## Prerequisites

- JDK 17, with `JAVA_HOME` pointing to the JDK directory. In Android Studio, also
  select JDK 17 as the Gradle JDK under Settings > Build, Execution, Deployment >
  Build Tools > Gradle.
- Android SDK Platform 37 (`platforms;android-37.0`).
- Android SDK Build-Tools 36.0.0 (`build-tools;36.0.0`).
- Android SDK Platform-Tools (`platform-tools`) for installing the APK on a device.

Install the SDK packages through Android Studio's SDK Manager, or with the
Android command-line tools:

```text
sdkmanager "platforms;android-37.0" "build-tools;36.0.0" "platform-tools"
```

Accept the required SDK licenses. Set `ANDROID_HOME` to your SDK directory, or
let Android Studio create an ignored `local.properties` with `sdk.dir`.
Keep SDK/JDK paths and `local.properties` out of version control.

## Clean verification

From the repository root, with JDK 17 selected:

```powershell
.\gradlew.bat --version
.\gradlew.bat clean test assembleDebug
```

On macOS/Linux:

```sh
./gradlew --version
./gradlew clean test assembleDebug
```

The first run downloads Gradle and Maven dependencies, so it needs internet
access. No system Gradle installation or connected Android device is needed
for these commands. `test` runs the configured JVM unit tests (debug variant);
`assembleDebug` builds `app/build/outputs/apk/debug/app-debug.apk`.
Unit-test reports are under `app/build/reports/tests/`.

## Build configuration

The wrapper uses Gradle 9.6.0 with distribution SHA-256 verification. The
project uses AGP 9.4.0 and its built-in Kotlin support, with Kotlin and the
Compose compiler plugin pinned to 2.3.21. Java and Kotlin target JVM 17;
built-in Kotlin inherits the Java target from `android.compileOptions`.

Do not reapply `org.jetbrains.kotlin.android` or disable the new AGP DSL.
See the official [built-in Kotlin migration guide](https://developer.android.com/build/migrate-to-built-in-kotlin)
and [AGP release notes](https://developer.android.com/build/releases/agp-9-4-0-release-notes).

## Wrapper generation

The wrapper scripts and JAR are generated by the official Gradle 9.6.0
`wrapper` task. To regenerate them using an installed Gradle 9.6.0 distribution:

```text
gradle wrapper --gradle-version 9.6.0 --distribution-type bin --gradle-distribution-sha256-sum bbaeb2fef8710818cf0e261201dab964c572f92b942812df0c3620d62a529a01
```

Commit both scripts and both files under `gradle/wrapper/`, preserving the
executable bit on `gradlew`. Never construct or hand-edit the wrapper JAR.
The generated URL must be
`https://services.gradle.org/distributions/gradle-9.6.0-bin.zip`.
